# Deployment (Proxmox LXC, no containers)

This is the target that Phase 7 implements. The scripts in `deploy/` must produce exactly this layout.

## LXC
- Template: Debian 13 standard. Unprivileged. Nesting is **not** needed.
- Resources:
  - 2 vCPU, 2 GB RAM (the Vite build likes memory; runtime needs far less)
  - 16 GB disk, which leaves room for receipts
- Networking: static IP or a DHCP reservation in UniFi. Enable "Start at boot".
- Timezone: set the LXC timezone to local time (`timedatectl set-timezone America/Detroit`) so the daily job
  and "today" line up with real life.

## Layout
| Path | Purpose | Owner |
|---|---|---|
| `/opt/payday-budget/` | Code checkout | root (readable by `payday`) |
| `/opt/payday-budget/backend/.venv` | Python venv (uv) | root |
| `/opt/payday-budget/frontend/dist` | Built SPA | root |
| `/etc/payday-budget/payday-budget.env` | Config, mode 0640 | root:payday |
| `/var/lib/payday-budget/budget.db` | Database | payday |
| `/var/lib/payday-budget/receipts/` | Attachments | payday |
| `/var/lib/payday-budget/backups/` | Nightly backups | payday |

The service runs as the system user `payday`, which has no login shell. Logs go to journald
(`journalctl -u payday-budget`).

## Environment file
```
PB_ENV=production
PB_DATA_DIR=/var/lib/payday-budget
PB_DATABASE_PATH=/var/lib/payday-budget/budget.db
PB_SECRET_KEY=<generated by install.sh>
PB_BASE_URL=https://budget.example.com
PB_TRUSTED_PROXY=<NPM LXC IP>
PB_MAX_UPLOAD_MB=10
PB_BACKUP_KEEP_DAYS=14
```

## systemd units (in `deploy/systemd/`)
**payday-budget.service**
```ini
[Unit]
Description=Payday Budget
After=network-online.target
Wants=network-online.target

[Service]
User=payday
Group=payday
EnvironmentFile=/etc/payday-budget/payday-budget.env
WorkingDirectory=/opt/payday-budget/backend
ExecStart=/opt/payday-budget/backend/.venv/bin/uvicorn app.main:app \
  --host 0.0.0.0 --port 8000 --workers 1 \
  --proxy-headers --forwarded-allow-ips=${PB_TRUSTED_PROXY}
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/payday-budget

[Install]
WantedBy=multi-user.target
```

Timers:
- **payday-budget-daily.timer / .service**
  - Runs `pb run-daily` hourly (`OnCalendar=hourly`, `Persistent=true`). Notifications wait until the
    reminder hour in Settings (D-068).
  - It runs as `payday` and uses the same hardening settings.
- **payday-budget-backup.timer / .service**
  - Runs `pb backup` with `OnCalendar=*-*-* 02:30:00` and `Persistent=true`.
  - The backup uses SQLite's online backup API (safe while the app runs), checks the copy with
    `PRAGMA integrity_check`, and makes a tarball of receipts. Each run writes a pair sharing one
    timestamp: `budget-YYYYmmdd-HHMMSS.db` and `receipts-YYYYmmdd-HHMMSS.tar.gz`.
  - Files older than `PB_BACKUP_KEEP_DAYS` are deleted; the newest pair is always kept.
  - If the backup fails, `OnFailure=` starts `payday-budget-notify-failure@.service`, which sends an
    urgent ntfy alert (D-073).

## NGINX Proxy Manager
Proxy host settings:
- Scheme `http`. Forward to the LXC IP on port `8000`.
- Block Common Exploits: on. Websockets: not needed.
- SSL tab: your certificate, Force SSL, HTTP/2.

If statement imports (over 1 MB) or, later, receipt uploads fail with 413, add `client_max_body_size 20m;` to the host's Advanced tab.

## Firewall
- Allow port 8000 **only from the NPM LXC IP**. Use the Proxmox firewall on the CT or nftables inside it.
- Allow SSH from the LAN only.

## Install (what `install.sh` does)
1. Install apt packages: `git curl sqlite3 python3 ca-certificates`, plus Node.js 20+ from Debian's own
   package if that version is new enough, otherwise from NodeSource.
2. Install uv.
3. Create the `payday` user and the directories above.
4. Fetch the code: clone from a git remote, or use a local path synced over with rsync.
5. Run `uv sync --frozen` and `npm ci && npm run build`.
6. Write the env file with a generated secret if it doesn't exist yet. Never overwrite an existing one.
7. Run `alembic upgrade head`.
8. Install and enable the units and timers.
9. Poll `/api/v1/health` until it responds.
10. Print the next step: `pb create-user`.

Running it a second time is safe.

## Update (`update.sh`)
1. Run `pb backup`.
2. `git pull` (or rsync).
3. `uv sync --frozen`.
4. `npm ci && npm run build`.
5. `alembic upgrade head`. **If this fails, stop and leave the old version running.**
6. Restart the service and run the health check. Print the version.

## Restore (`restore.sh <backup-file> [receipts-tarball]`)
0. Check the backup's integrity (and that the archive is safe to unpack) before touching anything.
1. Stop the service.
2. Keep a copy of the current database as `budget.db.pre-restore`.
3. Copy the backup into place and extract the receipts.
4. Run `alembic upgrade head` in case the backup came from an older version.
5. Start the service and run the health check.
6. If any step after the swap fails, put the previous database and receipts back and start the
   service again.

## Firewall choice
The Proxmox firewall on the CT, not nftables inside it (D-060). The rules are in `deploy/README.md`.

## Off-box protection
Include this LXC in the Proxmox vzdump schedule (e.g. to a PBS or NAS target). The app's nightly backups
give point-in-time copies. vzdump covers loss of the whole container.
